
## 内容搜索器 + 开发者分析前端（/discover）
- 用户要求：做“内容搜索器”，不仅学标题也学文章；关注文章热度，并分析是否符合 persona 偏好；并提供可供开发者分析的前端。
- 已实现：
  - 候选库与 API/UI：`/discover` 页面 + `content_discovery/discovery_store.py`（SQLite: `content_discovery/discovery.db`，支持 stats/items/import JSONL）
  - 自动注入 Tavily key：web_server 启动时从 `content-pipeline/config/secrets.json` 读取 `tavily.api_key` 设置 `TAVILY_API_KEY`（仅当 env 缺失）。
  - Tavily 采集器 + LLM 偏好判别：
    - `content_discovery/collector.py`（tavily_search + heat_score 启发式 + evidence）
    - `content_discovery/analyzer.py`（Kimi 调用给出 fit_score + reasons/evidence/tags JSON）
    - `scripts/discover_collect.py`（按 persona 默认 queries 批量采集→分析→upsert 入库）
  - /discover 前端增加“一键运行采集”按钮，后端 `POST /discover/api/run` 后台执行，日志落 `content_discovery/run_<task_id>.log`。

## 人设与偏好编辑前端（/personas）
- 用户要求：做一个人设与偏好窗口，展示当前值并允许修改；这些设定后续作为爬虫分析与文章生成依据。
- 已实现：`/personas` 页面可编辑并保存到 `content-pipeline/user_memory/*.md`：
  - 通用标题/正文：general_non_insurance
  - 用户专用标题/正文：<user_id>_title_style.md / <user_id>_article_style.md

## 主页与全站导航
- 用户要求：设置主页，前端随时进入其他页面，其他页面也能随时进入几个页面。
- 已实现：
  - 主页 `/`：工作台卡片链接到 `/library` `/query` `/discover` `/personas`
  - `/discover`、`/personas` 顶部 nav 增加“主页”链接
  - 用户反馈 `/library` 无主页按钮后，已补上文章库模板的全局 nav（含“主页”）。

## 环境/工具注意事项
- `memory_search` 工具当前不可用（Node runtime 缺 node:sqlite），已采用文件 grep/读取方式查历史配置。
- Tavily key 确实存在于 `content-pipeline/config/secrets.json`，但 OpenClaw `web_search` 仍依赖 BRAVE_API_KEY；因此搜索采集优先走 Tavily。
